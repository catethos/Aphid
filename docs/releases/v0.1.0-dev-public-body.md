# Aphid v0.1.0-dev — experimental native validation prerelease

No target is release-supported and no implementation stage is complete. Aphid
is not published to Hex. This prerelease contains native validation archives,
identity/audit records, checksums and retained third-party notice files; it
contains no bundled ERTS release.

Native Linux qualification: run `34193449987`. Refreshed source qualification:
run `34205212486`. One exact source package with SHA256
`11ca5ca447a7a93ee6d8e2d79758f3ed67d9ce04d20947a08e82598851152507`
passed 92 tests on native Linux x86_64/ARM64 and macOS ARM64 with fresh caches,
normal locked Hex dependency acquisition, denied native compiler/development-tree
access, and unchanged native hashes. That Hex source archive is not an attached
asset and is not GitHub's automatic source snapshot.

Linux ephemeral bundled-ERTS validation releases passed startup/restart,
offline shutdown/persistent reopen and startup failure checks. They are not
attached. The latest macOS qualification is a consumer proof; earlier macOS
bundled-ERTS evidence applies only to its original source package.

`SHA256SUMS` covers the eight Linux/notice payloads; `SHA256SUMS-macos` covers the
three macOS payloads. The source package installs the supplemental notice file
beside the native archive's license tree. The supplement's SHA256 is
`08cc1d20ccb4808537545220152d6aff97701e2c3b0b8597ab2dadaa82a789d1`.
The standalone notice attachment is not automatically fetched by native consumers.
The archived applications contain Aphid and Telemetry modules, with no bundled
Pegasus, ZigParser or NimbleParsec modules and no ERTS. Those parser packages are
build dependencies acquired separately. The retained native component map's
notice texts are present in the archive license trees plus the supplement.
Broader build provenance and production-runtime review remain follow-up work;
this is not an exhaustive attribution certification.

Execution is proved only on Ubuntu 24.04/glibc 2.39 and macOS 26.6, using Elixir
1.20.0 / OTP 29.0.4. Linux installation requires GNU objcopy; macOS requires
otool. The Linux engine requires GLIBC 2.38 and GLIBCXX 3.4.32. macOS native
commands declare 13.3; neither those declarations nor ELF requirements prove
minimum-system/CPU execution. Other OTP/binutils, x86_64-to-ARM64 cross-build,
fresh source installation and remaining implementation gates are unproved.
DuckDB stays 1.4.4.

The fixed tag's catalog URLs remain disabled. Public availability alone does not
prove package-default installation. A separately reviewed URL-enabled source
package must pass fresh consumers against the actual repository endpoint on all
three native targets. No silent source fallback or Hex publication is enabled.
