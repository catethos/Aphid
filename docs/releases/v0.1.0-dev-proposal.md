# Proposed private native-validation draft — authorization pending

This is a concrete draft-only proposal, not authorization to create a tag or
release. No public release, Hex publication or external maintainer message is
included. No target is release-supported; all existing plan gates remain open.

Proposed tag: `v0.1.0-dev`, signed using the existing configuration, at the final
signed preparation commit identified in the handoff. Proposed title:
`Aphid v0.1.0-dev — native review draft`. Keep both draft and prerelease flags set.

## Exact scope

The existing manual Linux workflow stages nine assets: the two qualified Linux
archives, their two identity records and two ELF audits, `THIRD_PARTY_NOTICES.txt`,
`THIRD_PARTY.md`, and `SHA256SUMS`. It retrieves the original native qualification
and the separately pinned successful current-source consumer qualification. No
native rebuild occurs. The full and version-specific asset hashes must pass the
local verifier before dispatch; a previous source-consumer pin is insufficient
when installer or shipped-notice bytes change.

The local macOS review helper stages four additional assets:
`runtime-validation-aarch64-macos-13.3-baseline-3.tar.gz`,
`aarch64-macos-identity.json`, `aarch64-macos-audit.json`, and `SHA256SUMS-macos`.
It binds the original archive to a reviewed macOS consumer of the identical
source package tested on both Linux architectures, compares current package
source, native inputs and installed hashes, and records otool output. These
files have not been uploaded to Actions or GitHub releases. After separately
explicit authorization covering all thirteen assets, the local macOS set can
be attached to the same private draft without overwriting any asset. Until that
step succeeds the draft is incomplete and must stay private.

`SHA256SUMS` covers the eight Linux/text assets; `SHA256SUMS-macos` covers the
three macOS assets. The two checksum groups deliberately have distinct names.
No bundled ERTS release archives or upstream extension/build archives are included.
The source package already contains and installs the supplemental text; no extra
notice network request or native repacking is required.

## Attribution and execution limits

The supplement preserves ten known retained notice texts. It does not establish
complete attribution or supply Pegasus/ZigParser's missing version-appropriate
full notices. No dependency source archives or bundled Erlang runtime are being
added to this draft. Final generated/linked-component mapping, modified-fork
review, NimbleParsec coverage and production runtime provenance remain open.
A private review draft is not public redistribution clearance.

Ubuntu 24.04/glibc 2.39 and macOS 26.6 are the tested execution systems. The
Linux engine requires GLIBC 2.38 and GLIBCXX 3.4.32; macOS native declarations
are 13.3. Neither establishes a tested minimum OS/CPU. GNU objcopy and otool
remain installer prerequisites. Other OTP/binutils versions, the required
x86_64-to-ARM64 cross-build, source installation and remaining Stage 05/07/08/09
gates remain open. DuckDB remains 1.4.4.

## Subsequent decisions remain separate

A draft is not an anonymous public download endpoint. Public publication needs
separate explicit authorization after review of the remaining attribution and
execution gates. Defaults stay disabled meanwhile. After authorized public
delivery, enable the independently package-pinned URLs and prove the final exact
source package using the real repository endpoint with empty caches and no
native compilers on all three required targets. Hex publication remains excluded.
